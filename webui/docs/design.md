# webui デザイン原則 — 「赤ペン×答案用紙」

導入スキル: Anthropic 公式 `frontend-design`（~/.claude/skills/frontend-design/）。
その流儀（題材の世界から意匠を採る・賭けは1箇所・AI既定ルックを避ける）で設計した。

## 3層の意味構造

色は装飾ではなく「誰が書いたか」を表す。

| 層 | 役割 | トークン |
|---|---|---|
| 紙 | 地。ほぼ白（クリームまで寄せない — AI既定ルック第1号を避ける） | `--paper #FCFBF7` / `--paper-dim` |
| 印刷罫 | 用紙に印刷されている側: 枠線・区切り・見出し罫・未採点の領域枠 | `--kei #A9BFB2` / `--kei-line` / `--kei-usu` / `--print-green`（確認済み文言） |
| 朱筆 | 先生が書き込む側だけ: 得点・進捗・採点カーソル・実行ボタン（採点行為） | `--shu #C73E2E` / `--shu-dark` / `--shu-usu` |

本文は墨 `--sumi #2B2825`、補助文は薄墨 `--usuzumi`。

**新しい色を足すときは、まず「それは紙・印刷・朱筆のどれか」を決めること。**
どれでもない色は原則いらない。

## 書体

- 見出し（h1/h2/ビュー題）と**得点の朱書き**だけ明朝（`--font-display`）
- 本文・操作はUIゴシック（`--font-body`）、パスとログは等幅（`--font-mono`）
- フォント同梱はしない（日本語フォントは重い）。Windows 標準の游明朝系で成立させる

## 署名要素（賭けはここだけ）

「朱の採点枠」— 選択中のカード/設問に朱の枠が付き、数字キーで朱書きの得点が
入って次へ送られる。赤ペンを持って答案の山を繰る動作そのものを署名にする。
得点の出現には捺印風アニメ `shu-stamp`（reduced-motion では無効）。
それ以外の装飾・アニメは足さない。

## 大量データの原則（400人×100問想定）

- 一覧は必ず仮想スクロール（`vlist.js` の `createVirtualGrid`）。
  カード高さは固定値を事前計算して渡す
- 画像は `createImageLoader` 経由（同時取得を絞る・LRU キャッシュ）。
  無制限に bridge を叩かない
- ビュー切替は `withTransition`（View Transitions API）。
  **遷移後にレイアウト計測するなら必ず await** — 反映前は clientWidth が 0
- キーボード動線を必ず用意する: 数字キー＝書いて次へ、矢印＝移動、
  BackSpace＝取り消し。マウスは常に併用可

## UI文言

- 能動態で、押した結果を正確に言う（「訂正をxlsxに反映」）。装飾絵文字は使わない
  （ログの ✓/❌/⚠ は状態記号として維持）
- 同じ操作は全ビューで同じ語彙（「未採点」「訂正」「答案」「設問」）
