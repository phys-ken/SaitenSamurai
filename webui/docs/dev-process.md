# webui 開発の進め方（Fable 大規模開発の運用ルール）

調査（2026-08-06）に基づく。このファイルは「どう進めるか」の正本。
「何を作るか」は plan.md（同ディレクトリ）、「どこまで進んだか」は progress.md。

## 4本柱

1. **計画・進捗のファイル外部化**: 作業はいつも progress.md を読んでから始める。
   1ステップ終えるごとに progress.md を更新。コンテキスト圧縮・モデル交代・
   セッション断で文脈が飛んでも、ファイルから完全に再開できる状態を常に保つ。
2. **緑→即コミット**: テストが緑になった単位で必ずコミット。作業ツリーを
   復旧点にする。壊れた状態でセッションを跨がない。
3. **サブエージェントは限定使用**: 本流は逐次的で設計判断が連鎖するため
   主コンテキストで行う。委譲するのは「独立・並列・自己完結」な作業のみ
   （例: 独立UIモジュールの実装、調査）。委譲時は必要最小の文脈だけ渡す。
4. **要約持ち越し**: マイルストーン完了時に progress.md へ3行要約を書き、
   詳細な経緯は捨てる。全履歴を引きずらない。

## トークン運用

- 長い出力（ビルドログ・テスト全文）は tail で絞る。全文が要る時だけ読む
- キャプチャ評価は「変更した画面だけ」撮る
- 定型確認（全回帰）はバックグラウンド実行し、待ち時間に別作業

## このリポジトリ固有の安全則

- tkinter GUI 3ファイル（main_gui / gui_components / descriptive_gui）は**不可侵**
- main_src ロジック層の変更が必要になったら「webui からも tk からも使える形」
  でのみ変更し、既存テスト1028件の緑を維持
- **root の requirements.txt と release.yml には触らない**（tk exe のリリース
  経路を汚さない。webui の依存は webui/requirements*.txt に隔離）
- main へのマージはユーザー承認後のみ
