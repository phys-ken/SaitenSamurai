# 採点侍 × LLM 協働採点 — エージェント向け手順書

このファイルは、先生と一緒に採点を進める AI エージェント（Claude Code・Antigravity など）が読む手順書です。
採点の処理はすべて `saiten_llm` のコマンドで行います。エージェントの仕事は、
**先生と対話しながらコマンドを順に実行し、黒塗り済みの写しを見て判断材料を作ること**です。

利用者は学校の先生です。採点結果が間違うと生徒の成績が壊れます。
速さより、正しさと、確認の記録を残すことを優先してください。

---

## 1. 絶対に守ること

1. **元の答案を見ない。** 次のものは開かない・コピーしない・中身を表示しない・別の場所へ送らない。
   - `projects/<試験>/scans/` の中すべて（採点侍の結果フォルダ `_saiten_grading_results/` も含む）
   - `projects/<試験>/除外/`
   - `projects/<試験>/*.pdf`

   見てよい画像は `projects/<試験>/_llm_view/` の中だけです（先生が黒塗りを承認した写し）。
   氏名などが写った画像を見てしまったら、作業を止めて先生に報告してください。
2. **黒塗りの画面（mask-server）の画像を取りに行かない。** URL は先生に伝えるだけです。
3. **先生の承認は、先生の言葉で得る。** 次のものは、先生がチャットで承認・確認を伝えるまで進めません。
   `--teacher-approved` や `confirm` を、先生の言葉なしに使ってはいけません。
   - モード／黒塗りの範囲（先生が画面で承認）／記述問題の範囲／採点基準
   - 記述の各問題の確定／正答／マークの確認／配点
4. **マークは LLM が判定しない。** 読み取りはすべて採点侍のルールベースの処理です。
   ノーマーク・複数マークは先生が採点侍の画面で目視します。
5. **画面を開いている間は先生の番。** 採点侍の画面（`open-ui`）を先生が閉じるまで、書き込むコマンドは動きません（終了コード 2）。
   待つだけにしてください。画面を閉じるよう急かさないでください。
6. **答案の中身を外へ出さない。** Web 検索や外部サービスに、答案の文・生徒の名前・番号を入れません。
7. 迷ったら推測で進めず、先生に聞きます。判断を保留した理由は必ず残します。

## 2. コマンドの使い方

採点侍のフォルダ（作業フォルダの `app/`）で実行します。

```
cd app
uv run python -m saiten_llm <コマンド> ../projects/<試験フォルダ> [オプション]
```

| 終了コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 失敗（表示された理由を読んで直す） |
| 2 | 先生の確認が必要（表示された内容を先生に伝えて待つ） |

`status` はいつでも実行してかまいません。`status --write` で `進捗.md` を書き直します（区切りごとに実行）。

## 3. 採点の流れ

先生が「`<PDF>` の採点を始める」と言ったら、次の順に進めます。各段階の終わりで `status --write` を実行します。

### 3-0. 環境チェック（毎回・必須）
```
doctor ..
```
✗ が1つでもあれば採点を始めません。結果を先生に伝え、許可を得てから直します。

### 3-1. 試験フォルダを作る
`projects/<試験名>/` を作り（名前は先生に聞くか、PDF の名前から提案）、PDF をそこへ**移す**（コピーを増やさない）。

### 3-2. 画像にして向きを揃える
```
pdf      ../projects/<試験>
orient   ../projects/<試験>            # 回す必要のある答案と、要確認の答案が出る
orient   ../projects/<試験> --apply    # 実際に回す
```
- 解答用紙が**横長（B4横など）**なら、最初の orient に `--landscape` を付けます（例: `orient ../projects/<試験> --landscape`）。
  付けないと横長の答案を縦に倒してしまいます。指定は project.json に残るので、2回目からは付けなくても効きます（縦長に戻すのは `--portrait`）。
  用紙の向きが分からなければ、先生に聞きます。
- 白紙・向きを決めきれない答案・マーカーの無い答案が混ざっていたら、一覧を先生に伝えます。
- 1枚目（基準）が正しい向きかは、次の黒塗りの画面で先生が確かめます。逆さだと言われたら `orient --flip-all`。

### 3-3. 黒塗り（先生の作業）
```
mask-server ../projects/<試験>     # バックグラウンドで実行する（先生の承認まで待つ）
```
- 表示された URL を先生に伝え、「氏名欄・番号欄など、見せたくない所をドラッグで囲み、
  全員分を確かめて承認してください」と頼みます。範囲は先生が決めます（複数でもよい）。
- 承認されると `_llm_view/pages/` に黒塗り済みの写しができます。これ以降、見てよいのはこの写しだけです。

### 3-4. モードを決める
```
facts ../projects/<試験>
```
- `_llm_view/pages/` の1枚目と facts の数字を見て、モード（マーク採点／マーク＋記述／記述のみ）と
  マーク形式（標準／数学の複数桁）を**根拠付きで**提案します。
- 先生の承認を得てから: `mode ../projects/<試験> --set <モード> [--format multi_digit] [--skip <ID欄の行数>] --teacher-approved`

### 3-5. マーク（マークのあるモード）
```
coord      ../projects/<試験> <座標ファイル.xlsx>   # 座標ファイルは先生が用意する
recognize  ../projects/<試験>
```
- `coord` の後、`_llm_view/coord_check.jpg` を見て、緑の枠がマーク欄に、赤い枠が設問の行に重なっているか確かめます。
  問題数・選択肢数が用紙の見た目と合うかも確かめます。ずれていれば先生に伝えます（取り違えの疑い）。
- `recognize` で「マークが1つだけの答え」が少ないと警告が出たら、座標ファイルの取り違えを疑います。
- ノーマーク・複数マークなどは、先生が採点侍の「マークの確認」で目視します（`open-ui`）。
  先生が「マーク確認しました」と言ったら: `confirm ../projects/<試験> marks`

**正答**（形式は問わない。先生から受け取ったものに合わせる）
- 先生が埋めた Excel: `answer-key ... --from-xlsx <ファイル>`（中身は書き換えない）
- チャット・画像・テキストで受け取った: JSON に書き写して `answer-key ... --from-json <ファイル>`
  （`{"rows": [{"問題番号": 1, "正答": "3"}, ...]}`。配点は仮に1点）
- 正答をマークした用紙: 読み取った後に `answer-key ... --from-sheet <ファイル名>` → `set-aside ... <ファイル名> --reason 正答用` → もう一度 `recognize`

出力された一覧を先生に見せ、「この正答で合っていますか」と確かめます。
承認されたら: `confirm ../projects/<試験> answer-key`

### 3-6. 記述（記述のあるモード）
記述のみのモードでは、先に `prepare ../projects/<試験>` を実行します。

**範囲** — `_llm_view/pages/` の1枚目を見て、問題ごとの解答欄の範囲を画素で決め、JSON に書きます。
```
{"questions": [{"name": "問1", "region": [x1, y1, x2, y2]}, ...]}
desc-set ../projects/<試験> --input <JSON>
```
- **四隅のマーカーが無い用紙**（`facts` でマーカー 0 枚）は傾きを補正できません。範囲は解答欄の枠より
  **上下左右に20画素ほど広く**取ります（わずかな傾きでも、枠の端で10画素ほどずれるため）。
  黒塗りの範囲も、先生に少し広めに囲んでもらうよう伝えます。

`_llm_view/desc_regions.jpg` で範囲を確かめてから、先生に採点侍の「記述問題の設定」で確かめてもらいます（`open-ui`）。
先生が承認したら: `confirm ../projects/<試験> regions`

**採点基準** — 先生から模範解答を受け取り、`projects/<試験>/採点基準.md` の案を作ります（形式は 5 章）。
先生がチャットで承認するまで、判定を始めません。

**並べた画像** — 同じ問題の切り抜きを番号付きで並べます。
```
crops ../projects/<試験> --question D1 --per-sheet 15
```
- 1枚に並べる人数は 10〜20。字が小さい問題は減らします。本番の前に数問で人数を変えて、読み違いが出ないか確かめます。
- 番号は問題ごとの通し番号です。画像にはファイル名がありません。

**判定** — 採点基準に照らして、番号ごとに判定します。
```
{"1": "正", "2": {"verdict": "部分", "reason": "単位がない"}, "3": {"verdict": "保留", "reason": "別解の可能性"}}
judge ../projects/<試験> --question D1 --input <JSON>
```
- 判定は **正 / 部分 / 誤 / 保留** の4つだけ。確認中は仮の2点満点で記録されます（正=2・部分=1・誤=0・保留=未採点）。
- **保留**: 採点基準で決めきれないもの（想定外の別解・判読できない字など）。理由を必ず書きます。
- **部分**: 部分点に当たりそうなもの。理由を必ず書きます。最終の点数は、配点を決めるときに先生が決めます（3-7 の `"partial"`）。決めなければ先生が個別に入れます。
- 判定の理由の要点は、チャットでも先生に伝えます。

**先生の確認** — `review` で保留・部分を一覧にして先生に伝え、`open-ui` で採点侍を開きます。
先生は画面で、保留に点を入れ、誤りを直します。並び順は 保留 → 部分 → 誤 → 正 で見てもらうよう勧めます。
先生が「問3確認しました」と言ったら: `confirm ../projects/<試験> question --question D3`
（未採点が残っていると確定できません。その場合は残りを先生に伝えます）

### 3-7. 配点
全問の確定・正答・マーク確認がそろってから進みます。
```
stats ../projects/<試験> --total 100     # 満点が100点でないときは先生に聞く
```
- 正答率・識別力と、配点案（全問同じ重み・難しい問題を重く・識別力の高い問題を重く）を先生に示します。
- **識別力がマイナスの項目**は、出題や正答の誤りの疑いとして、配点の話より先に伝えます。
- 配点に決まった規則はありません。先生が個別に判断します。案を選ぶ・直すのは先生です。
- 先生が承認したら JSON に書いて:
```
{"marks": {"1": 2, "2": 3, ...}, "descriptive": {"D1": 10, "D2": 2}, "partial": {"D1": 5, "D2": 1}}
set-points ../projects/<試験> --input <JSON> --teacher-approved
```
- マークを answer_key.xlsx の配点のまま使うなら `"marks": "keep"`。
- 記述は 正→満点・誤→0 に換算されます。部分は:
  - **`"partial"` に書いた問題**は、その点数になります（1 点以上・満点未満の整数）。
    全問共通の割合で決めるなら `--partial-ratio 0.5`（満点×割合を四捨五入。`"partial"` に書いた問題はそちらが優先）。
  - **どちらも指定しない問題**は、部分が**未採点に戻ります**。先生に採点侍で「未採点」に絞り込んで
    点を入れてもらい、終わったら `confirm ... question --question <ID>` で確定し直します。
- 換算の後に未採点が残らなければ、先生の確定は換算した点数のまま引き継がれます（確定し直さなくてよい）。
  ただし、確定の後で画面の得点が変わっていたら引き継がず、確定し直しを頼みます。
- 満点を 2 点のまま（正 2・部分 1・誤 0）にするなら `{"descriptive": {"D1": 2}, "partial": {"D1": 1}}`。点数は変わらず、確定だけが保たれます。
- `stats` は 得点÷満点 で計算します。配点を決める前の部分は 1/2 として数えるので、部分の点を満点の半分以外にするときは、
  set-points の後にもう一度 `stats` を実行すると、その点数での正答率・識別力が出ます（配点案は参考）。

### 3-8. 個票の見た目（finalize の前に必ず）
個票（返却答案）の実物は元画像から作るので、エージェントは開けません。
見た目は、黒塗り済みの写しの上に同じ関数で描いた**プレビュー**で確かめ、先生にも見てもらってから finalize します。
（いまは記述のみモードだけ。マーク式の個票は、採点侍の画面の「位置プレビュー」で先生に確かめてもらいます）
```
render-settings ../projects/<試験>                     # いまの設定（* が既定から変えたもの）
render-settings ../projects/<試験> --set descriptive_show_aspect=false total_show_aspects=false
```
- **観点を使わない試験**（小テストなど）では、観点を消します（`descriptive_show_aspect=false`・`total_show_aspects=false`）。
  定期試験など観点を使う試験は既定（表示）のまま。迷ったら先生に聞きます。
- 解答欄に得点の数字を出すかは `descriptive_show_score`（既定は出す）。先生の希望に合わせます。

**合計点の枠は、エージェントが目で見て決めます**（自動の検出には頼りません）。
枠を決めないと、合計点は答案の左下（既定の位置）に小さく描かれ、問題文に重なることがあります。
1. 黒塗り済みの1枚目（`_llm_view/pages/`）を見て、合計点を書く欄（「得点」欄など）がどこにあるかを確かめる。
2. 座標を読む:
   ```
   total-region ../projects/<試験> --crop                     # 右上の隅を拡大し、目盛りを重ねる
   total-region ../projects/<試験> --crop 2300,0,2866,300     # 範囲を決めて拡大（原寸の画素）
   ```
   `_llm_view/total_region_crop.jpg` の目盛りの数は**原寸の画素**です（50 画素ごと・太い線は 100 の倍数）。
   画像の表示の倍率を掛けず、目盛りの数をそのまま読みます。
3. 枠を設定する: `total-region ../projects/<試験> --set x1,y1,x2,y2`
   - 合計点は**枠の上端から**描かれます（`draw_combined_total` は枠の上端から 2 画素の所に書く）。
     欄の上の方に見出し（「得点」など）があるときは、見出しに重ならないよう、**欄の下半分**を枠にします。
   - 欄が縦の線で2つに分かれて見えても、1つの欄のことがあります。拡大した画像で確かめます。
4. 重ね描きで確かめる: `--set` のあと、設定した枠（赤）を重ねた画像が書かれます
   （`_llm_view/total_region_crop.jpg` が拡大・目盛り付き、`_llm_view/total_region.jpg` が1枚目の全体）。
   枠が欄の中（見出しの下）に乗っているかを見て、ずれていれば読み直して `--set` し直します。
5. `render-preview ../projects/<試験>` で、合計点が欄の中で読めるかを確かめる（`_llm_view/preview/` に、合計点の低い・中・高の3枚）。
6. 先生に見せて了解をもらう。先生が自分で囲みたいときは、`total-region-server ../projects/<試験>`
   （バックグラウンドで実行）で、先生が画面で欄を囲み、試し描きを見て承認します（黒塗りと同じ操作）。

- `total-region --detect` は**ヒント**です。「得点」欄らしい四角を探して、拡大した画像に緑で重ねます
  （`--detect --apply` で、その下半分を枠にする）。取り違えたり見つからなかったりするので、結果は必ず画像で確かめます。
  見つからなくても失敗ではありません（終了コード 0）。
- `render-preview` の画像で、○×△の大きさ・合計点が欄に収まっているかを確かめ、先生に見せて了解をもらってから 3-9 へ。
  プレビューに入らないのは、採点侍の画面で書いた手書きのコメントだけです。

### 3-9. 個票と集計
```
finalize ../projects/<試験>
```
- 確認がそろっていなければ作りません（終了コード 2）。残っていることを先生に伝えます。
- できたら、出力先（`scans/_saiten_grading_results/02_Graded_Detail` と `03_Final_Report`）を先生に伝えます。
  中身は元画像から作られた返却用なので、エージェントは開きません。

### 3-10. ふりかえり
```
accuracy ../projects/<試験>     # LLM の判定と先生の確定の一致（精度.json にも残る）
audit ..                       # 元の答案に触れようとした形跡がないか
```
両方の結果を先生に伝えます。食い違いの多い問題は、次回の採点基準づくりに生かします。

一致の数え方（`accuracy`）:
- **保留**は一致率の分母に入れず、「保留 N」として別に数えます（LLM が判定しなかったものなので）。
- 先生の点がまだ入っていない答案（未採点）も分母に入れません。
- 正は満点、誤は 0 点、部分は 0 点より大きく満点より小さい点なら「一致」です。
- `review` の「先生の修正」も同じ考えで、保留に先生が点を入れた分は修正に数えません。

## 4. 進捗.md

`status --write` が書く `projects/<試験>/進捗.md` は、先生とエージェントの共通のメモです。
会話が途切れても、このファイルと `project.json` から続きを再開できます。
自由記述欄（「メモ」の見出しの下）には、先生とのやりとりで決めたこと（満点・別解の扱いなど）を書き足します。

## 5. 採点基準.md の形式

```
# 採点基準 — <試験名>

## D1 問1（範囲の名前）
- 模範解答: 光合成
- 正: 「光合成」。ひらがな「こうごうせい」も正（先生 10/22 承認）
- 部分: 漢字の誤字が1字（例「光合せい」）
- 誤: 呼吸、無答
- 保留にするもの: 上のどれにも当たらないもの
```
先生が承認した内容と日付を書き残します。判定の途中で基準を足したら、先生の承認を得てから書き足します。

## 6. ファイルの地図（1つの試験）

```
projects/<試験>/
  <答案>.pdf            先生が渡した PDF（見ない）
  scans/                PDF を画像にしたもの・採点侍の結果（見ない）
  除外/                 集計から外した答案（見ない）
  _llm_view/            見てよい写し（黒塗り済み）
    pages/              全答案（傾き補正・黒塗り済み）
    coord_check.jpg     座標の枠を重ねた1枚目
    desc_regions.jpg    記述の範囲を重ねた1枚目
    crops/<問題ID>/     並べた画像と index.json
  project.json          コマンドの記録（承認の日時など）
  judgments.json        記述の判定と理由・先生の確定
  配点の検討.json        stats の数値
  採点基準.md / 進捗.md  先生と共有するメモ
```
