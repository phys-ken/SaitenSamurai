# UX 磨き込み計画（機能追加なし・ファイル互換完全維持）

grill-me で確定（2026-08-26）。参照知見: デジタル庁デザインシステム（日本語UI・
アクセシビリティ）、progressive disclosure / ツールチップ設計の定石。

## 原則

- 機能は増やさない。**見せ方・順序・言葉**だけを変える
- フォルダ名・ファイル名は互換のため不変。画面は**役割語を主、実名を従**
  （例:「読み取り結果（Mark2-Result…xlsx）」）
- 既定で見せるのは必須のものだけ。詳細は ℹ ポップオーバーと折りたたみの背後に
- ラベルは能動態で「押すと何が起きるか」を書く

## フェーズ A: 進行の可視化と言葉

1. **常設ステッパー**: 「準備 → 読み取り → 採点 → 集計」。完了=✓（青磁）、
   現在地=朱。既存 state から導出（bridge に読み取り専用の progress 集計を追加）。
   下に「ここまでの内容は自動保存されています」を常設
2. **ℹ ポップオーバー基盤**: ホバー/クリック/キーボードフォーカスで開く。
   数行の解説＋「→ 用語とファイルの地図」リンク。`title` ではなく自前
   （タッチ・複数行・リンク対応）
3. **用語刷新**（主な対応表）
   | 旧 | 新（画面表示） |
   |---|---|
   | Step 1: 認識 | ① 答案を読み取る |
   | Step 2: 採点 | ② 採点する |
   | Step 3: 集計 | ③ 集計してまとめる |
   | 画像フォルダ | 答案画像フォルダ |
   | 座標ファイル | マーク位置の定義 ℹ（座標ファイル） |
   | 正答データ | 正答・配点 ℹ（answer_key.xlsx） |
   | OMR結果 | 読み取り結果 ℹ |
   | Skip（ID欄の数） | ID欄の列数 ℹ |
   | 認識実行 | ▶ 答案を読み取る |
   | 画像準備 | ▶ 画像を準備する |

## フェーズ B: 出力の設定とファイルの地図

4. **「出力の設定」集約**: Step2 の直前に折りたたみセクション（既定は閉）。
   中身=答案に描くもの（表示項目の設定）／合計点の位置／集計シートの氏名画像／
   記述を分析に含める。Step パネルには実行ボタンだけが残る
5. **「用語とファイルの地図」ビュー**: アプリ内ページ。結果フォルダの木構造と
   「何が入るか・消してよいか・どのステップが作るか」。全 ℹ から到達できる
6. **結果フォルダ README**: 読み取り/画像準備の完了時に、結果フォルダへ
   短い README.txt を書き出す（地図の要約）

## フェーズ C: 文書

7. **README.md 全面改稿**（教員目線）: 3分クイックスタート／中断と再開／
   フォルダとファイルの地図／よくある質問。webui 前提に書き直す
8. DEVELOPMENT.md は目次と webui 節の追記のみ。docs/ に地図の原本を置き、
   アプリ内ビューと内容を一致させる

## 検証

- 各フェーズで L2 テスト（ステッパー状態遷移・ポップオーバー開閉・
  設定集約の表示）と Xvfb キャプチャ → 自己批評 → 修正
- 既存テストはラベルでなく ID 参照のため原則無風。文言アサートのみ追随
